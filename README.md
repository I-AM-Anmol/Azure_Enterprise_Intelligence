# Azure Budget Analysis — MedInsight FinOps Dashboard

A real-time Azure subscription budget tracking system built on **Microsoft Fabric**, **Power BI Semantic Model**, and **Streamlit**. Monitors month-to-date spend, daily burn rate, and budget alert thresholds across all MedInsight Azure subscriptions.

## Components

### 1. Fabric Notebook 2 — Data Engine

**File:** `FABRIC collection Codes/FABRIC_BudgetAnalyzer.py`

This PySpark notebook runs inside Microsoft Fabric and is the sole data producer. It has no UI — it queries Azure APIs and writes structured JSON to the Lakehouse.

**What it does:**

| Step | Action |
|------|--------|
| **Auth** | Authenticates to MedInsight Production tenant via Service Principal (`ClientSecretCredential`) |
| **Step 2** | Discovers all enabled Azure subscriptions via `/subscriptions` API |
| **Step 3** | Fetches budget definitions for every subscription in parallel (50 workers) via `Microsoft.Consumption/budgets` |
| **Step 3b** | Fetches real month-to-date actual spend for every budgeted subscription (8 workers) via `Microsoft.CostManagement/query` with `ActualCost / MonthToDate` |
| **Compute** | Calculates `pctUsed`, `dailyBurnRate`, `projectedEOM`, alert gaps, days-to-threshold, and status per subscription |
| **Write** | Saves `BudgetData.json` to Lakehouse Files via local mount → notebookutils fallback → OneLake DFS REST API |

**Cell 2 (separate cell — run after Cell 1):**
Reads `BudgetData.json` from Lakehouse Files and writes it as a Delta table so the Semantic Model can read it.

```python
path = f"abfss://{WORKSPACE_ID}@onelake.dfs.fabric.microsoft.com/{LAKEHOUSE_ID}/Files/BudgetData.json"
df = spark.read.option("multiLine", "true").json(path)
df.write.format("delta").mode("overwrite").saveAsTable("BudgetData")
```

**Rate limiting note:** The Cost Management API throttles aggressively under parallel load. The notebook uses 8 workers (not more) and fully respects the `Retry-After` response header to avoid subscriptions returning `$0` due to exhausted retries.

### 3. Streamlit App — Budget Analysis Page

**File:** `pages/2_Budget_Analysis.py`

The frontend dashboard. Has no direct Azure connection — all data comes from the Fabric Semantic Model via Power BI REST API.

**Authentication:**
Uses MSAL Device Code Flow (`PublicClientApplication`). On first load, the user is shown a one-time code and directed to `microsoft.com/devicelogin`. After sign-in, the token is cached in `st.session_state` for the browser session.

**Data flow:**
```
Power BI REST API (executeQueries)
→ EVALUATE BudgetData (DAX)
→ pandas DataFrame
→ Streamlit UI
```
Data is cached for 5 minutes (`@st.cache_data(ttl=300)`) and the page auto-refreshes every 5 minutes.

**Dashboard features:**

- **KPI Cards** — Total Budget, Actual Spend MTD, Daily Burn Rate, Projected Month-End, Status Summary
- **Month Progress Bar** — visual showing today's position vs spend % vs projected end-of-month
- **Status Pills** — Over Budget / Critical / Warning / Watch / OK counts at a glance
- **Filter Bar** — filter by status (segmented pill control) and search by subscription name
- **Budget Table** — one row per subscription with:
  - Budget amount, Actual MTD spend
  - Visual progress bar with budget line + Alert 1 + Alert 2 markers
  - % Used, Daily burn rate, Projected end-of-month
  - Alert 1 & Alert 2 — threshold %, dollar amount, gap remaining, days until crossed
  - Remaining budget, Status badge, Owner email (from alert contacts)
- **CSV Export** — downloads the filtered view
- **Row highlighting** — red tint for Over Budget rows, orange tint for Watch rows

**Status definitions:**

| Status | Condition |
|--------|-----------|
| `OVER BUDGET` | Actual spend > budget amount |
| `CRITICAL` | % used ≥ Alert 2 threshold |
| `WARNING` | % used ≥ Alert 1 threshold |
| `WATCH` | Status OK but projected EOM > budget (will exceed by month end) |
| `OK` | All within limits |

## Data Fields Reference

The `BudgetData` table produced by the notebook contains the following fields:

| Field | Description |
|-------|-------------|
| `subscription` | Azure subscription display name |
| `tenantName` | Tenant the subscription belongs to |
| `budgetName` | Name of the budget resource |
| `budgetAmount` | Monthly budget limit (USD) |
| `actualSpend` | Month-to-date actual spend from Cost Management API (USD) |
| `pctUsed` | `actualSpend / budgetAmount × 100` |
| `remainingUSD` | `budgetAmount − actualSpend` |
| `dailyBurnRate` | `actualSpend / days elapsed this month` |
| `projectedEOM` | `dailyBurnRate × days in month` |
| `daysRemaining` | Days left in the current month |
| `alert1Pct` | Alert 1 threshold percentage |
| `alert1Threshold` | Alert 1 threshold in USD |
| `alert1GapUSD` | USD gap between actual spend and Alert 1 threshold |
| `alert1DaysAway` | Estimated days until Alert 1 is crossed (at current burn rate) |
| `alert1Recipients` | Semicolon-separated email list from alert contacts |
| `alert2Pct` | Alert 2 threshold percentage |
| `alert2Threshold` | Alert 2 threshold in USD |
| `alert2GapUSD` | USD gap between actual spend and Alert 2 threshold |
| `alert2DaysAway` | Estimated days until Alert 2 is crossed |
| `status` | `OK` / `WARNING` / `CRITICAL` / `OVER BUDGET` |
| `generatedAt` | UTC timestamp when the notebook ran |

## Known Limitations

- **Budgeted subscriptions only** — the report currently shows only subscriptions that have an Azure Budget resource defined. Subscriptions without a budget are not included.
- **Data freshness** — data is only as current as the last Notebook 2 run. There is no automatic schedule; the notebook must be triggered manually or via a Fabric Data Pipeline.
- **Rate limiting** — the Azure Cost Management API throttles requests per service principal. The notebook is configured to use 8 parallel workers and respect `Retry-After` headers to avoid returning `$0` for throttled subscriptions.
